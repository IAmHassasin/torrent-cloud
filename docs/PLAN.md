# Torrent Cloud — Plan

## Goal

One command on the user's machine sends a torrent (magnet link or `.torrent` file) to a
cloud worker. The worker downloads it, uploads the result to a storage backend and returns a
fast, expiring HTTPS download link.

```
tc add "magnet:?xt=urn:btih:..." --wait
# ... 100%  12.4 MB/s  ...
# https://storage.example.com/torrent-cloud/<job>/file.iso?X-Amz-Signature=...
```

For now the "cloud" is a local Docker Compose stack; the same images run unchanged on any VPS.

## Architecture

```
 tc (CLI)  ──HTTP + Bearer token──►  api (Node/TS, Fastify)
                                        │  JSON-RPC (secret token, internal network only)
                                        ▼
                                     aria2c (BitTorrent engine, DHT, trackers)
                                        │  shared volume /downloads
                                        ▼
                                     uploader (inside api) ──S3 API──► SeaweedFS / S3 / R2 / B2
                                        │
                                        └── presigned GET URL (expiring) ──► returned to tc
```

| Component | Choice | Why |
|---|---|---|
| Torrent engine | `aria2c` 1.37 (Alpine package) over JSON-RPC | Battle-tested, magnet + DHT + web seeds, used by `mirror-leech-telegram-bot` and `aria2.conf` refs |
| API / worker | Node 22 + TypeScript + Fastify | Same language as CLI, small footprint |
| Job store | `node:sqlite` (built-in) | No native deps; single worker is enough for MVP |
| Storage | S3-compatible (SeaweedFS 4.48 locally) + `local` provider (HMAC-signed URL served by api) | S3 API covers AWS S3, Cloudflare R2, Backblaze B2, Wasabi, MinIO, SeaweedFS |
| Link | S3 presigned GET (default 24h, max 7 days) | Bucket stays private; link is fast (direct from object storage) |
| CLI | Node 22, zero runtime deps | `npm i -g` or `node cli/dist/tc.js` |

## Job lifecycle

`queued → downloading (metadata → data) → uploading → done` or `failed` / `cancelled`.

- Magnet: aria2 first downloads metadata in a separate gid, then the real download gid is
  in `followedBy[0]`; the worker follows it (verified in `mirror-leech-telegram-bot`).
- `seed-time=0` by default: stop seeding once complete (configurable `SEED_TIME_MIN`).
- Multi-file torrents: each file is uploaded and linked; `--zip` bundles everything into one
  archive first.
- After upload the local copy is deleted (configurable `KEEP_LOCAL=false`).

## API (v1, all routes require `Authorization: Bearer <TC_API_TOKEN>`)

| Method | Path | Body / result |
|---|---|---|
| POST | `/v1/jobs` | `{ magnet }` or `{ torrentBase64 }`, optional `{ zip, provider }` → job |
| GET | `/v1/jobs` | list |
| GET | `/v1/jobs/:id` | job with progress, speed, files, links |
| DELETE | `/v1/jobs/:id` | cancel + cleanup |
| GET | `/healthz` | no auth, liveness only |
| GET | `/files/:token` | `local` provider only, HMAC-signed expiring token, no bearer |

## Security decisions

- API token, aria2 RPC secret and storage credentials come only from `.env` (generated by
  `scripts/gen-env.mjs`, git-ignored). `.env.example` contains placeholders only.
- aria2 RPC is not published to the host; the SeaweedFS S3 port is published on `127.0.0.1` only (needed to
  open presigned links locally). API is published on `127.0.0.1` only.
- No SSRF: the API accepts only magnet URIs and raw `.torrent` bytes, never arbitrary URLs.
  The CLI downloads a `.torrent` URL itself and uploads the bytes.
- File paths reported by aria2 are resolved and must stay inside `/downloads`.
- Bucket is private; links are presigned and expire.
- Token comparison is constant-time. Tokens and signed URLs are never logged.

## Verification of technical assumptions

| Assumption | How verified | Result |
|---|---|---|
| aria2 available in Alpine | `docker run alpine:3.22 apk add aria2` | aria2 1.37.0 |
| Magnet produces follow-up gid | Read `refs/mirror-leech-telegram-bot/.../aria2_listener.py` | `followedBy[0]` pattern |
| Stop seeding after completion | `refs/aria2.conf/aria2.conf` + aria2 docs | `seed-time=0` |
| `node:sqlite` works without flags | `docker run node:22-alpine node -e "require('node:sqlite')"` | works (experimental warning) |
| Presigned link works from host | `npm run demo` downloads via presigned URL and compares SHA-256 | PASSED (64 MB, sha256 match; zip size match) |
| MinIO image usable | `docker pull minio/minio` | **No**: repository no longer on Docker Hub, quay.io needs auth → switched to `chrislusf/seaweedfs:4.48` (Apache-2.0) |
| Works on a real swarm | Big Buck Bunny torrent from archive.org | 420.9 MB in ~5 min, 13 links OK; tampered/unsigned access → 403 |
| Long link tokens route correctly | unit test `flow.test.ts` | Needed `maxParamLength: 2048` (Fastify default 100) |

## Demo plan

1. `docker compose up -d --build` (aria2, api, storage).
2. `docker compose -f docker-compose.yml -f docker-compose.demo.yml up -d seeder` — a private
   HTTP tracker + aria2 seeder that seeds a generated file (fully offline, deterministic).
3. `tc add <demo magnet> --wait` → link → download the file via the link → SHA-256 equals.
4. Optional real-world run: a public-domain torrent from archive.org (has web seeds).

## Out of scope for MVP / next steps

- Multi-user accounts and quotas (single shared token now).
- Additional providers: rclone (Google Drive, OneDrive), Telegram, gofile.
- Horizontal scaling (Redis queue), streaming while downloading, web UI beyond a status page.
- TLS termination (put Caddy/Traefik in front when deploying to a VPS).
